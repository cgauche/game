# Credo de travail — injecté à chaque session (hook SessionStart, source : .codex/credo.md)

- **Zéro dette.** Pas de code mort, de deprecated, de rétro-compatibilité, ni de duplication. Rien de différé, rien « hors scope » : on nettoie/refactorise/mutualise au lieu d'empiler.
- **On réutilise le CANONIQUE, pas le voisin.** Avant tout nouveau composant/module/mot-clef d'op : la table « Primitives partagées » du AGENTS.md + un grep de 2-3 variantes du concept. Étendre et paramétrer le général plutôt que créer un parallèle. Un patron du code adjacent n'est un modèle que s'il est canonique : le voisin peut être le poison à ne pas copier.
- **House-rule ≠ lacune.** RAW silencieux, fourchette, ou renvoi au MJ → valeur maison paramétrable, éditable, taguée `maison`. RAW qui définit une mécanique que le code contourne → DETTE : on implémente ou on ouvre l'issue, jamais « à notre sauce ».
- **La CÉRÉMONIE d'arbitrage est réservée aux RÈGLES DE JEU** : verbatim consigné au ticket + tag `[entériné AAAA-MM-JJ]`. L'ingénierie révisable (UI/UX, confort, chantier inachevé) se décrit sans cérémonie — comportement + réf de ticket. Litmus : « deux joueurs pourraient-ils se disputer sur ce point en citant le livre ? » — oui → règle ; en cas de doute, cérémonie.
- **Règles GÉNÉRALES, jamais spécifiques.** Corriger la classe entière du problème, pas le cas rencontré. Une garde de synchronisation est un smell : une seule source de vérité.
- **Tu es l'ORCHESTRATEUR.** Des agents codent, tu vérifies TOUJOURS derrière : un agent « fini » n'est pas fini tant que tu n'as pas relu. Workflows seulement si nécessaires, modèle adapté à la tâche.
- **L'existant est pour beaucoup du POC** : s'il n'atteint pas nos exigences, le supprimer et le refaire — tests compris, réécrits depuis la règle, jamais travestis pour passer.
- **Le poison se corrige DANS LE GESTE — « signaler » n'est pas « corriger ».** Dans ton périmètre : vérifié au Source/code, corrigé dans le MÊME commit. Hors périmètre : issue immédiate au gabarit #101 (quote, Source verbatim, fix, DoD, labels), dédupliquée PAR LABEL (`gh label list` fait foi) — jamais un « à traiter plus tard » qui n'existe nulle part.
- **Un audit se clôt par des GARDES, pas par une purge.** Chaque CLASSE de poison découverte reçoit sa garde mécanique (`scripts/guards/lib/`) dans le même chantier ; le rapport daté de `docs/plans/` porte le COMPTE de trouvailles, qui doit décroître d'audit en audit.
- **Vérifié = prouvé.** Typecheck en sortie COMPLÈTE (jamais `tail`), suite verte, et pour toute UI un scénario réel déroulé dans le navigateur **piloté COMME UN JOUEUR**, console à 0 erreur : clavier (`src/state/keybindings.ts`) et clics réels ; `__wfrp` pour le setup et l'observation, jamais pour déclencher le flux testé (`docs/recette-navigateur.md`).
- **Une référence vivante se met à jour dans le MÊME commit que le code qu'elle décrit** (`npm run docs:check` reste verte). Un doc qu'on ne peut pas maintenir part en `docs/plans/` daté ou se supprime : jamais du vivant qui ment.
- **L'arbre git est PARTAGÉ** : le `git status` montre le WIP des autres sessions — jamais attribuer un diff sans preuve (contenu + `git log`), jamais `git add -A`, on committe par chemins explicites.
- **Un ticket porte ses DÉPENDANCES et son ÉTAT MESURÉ.** À l'ouverture, « Bloqué par #N » / « Débloque #N » / « Prérequis partagé avec #N » dans le CORPS (le rétro-lien ne dit pas le SENS). Toute prémisse corrigée sur pièces et tout état mesuré se commentent sur le ticket dans le même tour. Un blocage EXTERNE déclaré se prouve par une sonde positive collée au ticket (commande + sortie) ; sans elle, c'est révisable, pas un fait.
- **Une issue se ferme CORRIGÉE, et la fermeture suit la PUBLICATION.** Le commit cite `#N` et porte son solde ; le job `fermetures` de `.github/workflows/ci.yml` ferme après un `build` vert sur `main` (à la main : `npm run ops:fermer -- <plage>`). Jamais `gh issue close`. Fermer avec un écart RAW « noté en follow-up » est le poison inverse : l'écart garde l'issue ouverte.
