Trois abstractions unifiantes (contenu extensible SANS toucher au code applicatif) :

- **A. Règles optionnelles** (`src/engine/policy.ts` : registre `OPTIONAL_RULES`, 1 règle = 1 entrée + store de surcharge + `rule(id)`) — activables EN JEU (`HouseRulesModal` généré depuis le registre, persisté `wfrp4.house-rules.v1` via `state/houseRules.ts`). `getTestPolicy()` (`engine/testPolicy.ts`, type `TestPolicy`) = SEUL décideur de la résolution d'un Test d100 : `evaluateTest`/`rollTest`/`maxForcedRoll` (`tests.ts`) la LISENT (bandes auto 01-05/96-00 réglables, `bandsMode`, `slMode`, bornes de cible). Le registre `OPTIONAL_RULES` porte le catalogue (~79 entrées) — dont Voyage par Étapes (`travelStages.ts`), couche sociale de Statut (`engine/social.ts`), Longueur d'arme (`weaponReachPenalty`).
- **B. Content-effects** : `GameOp` (`engine/ops.ts`) exécuté par `applyOps` — le contenu vit en DONNÉE, jamais en code par entité. Cultes/bénédictions/miracles dans `src/data/gods.json` ; psychologie lue par `parsePsychTraits` (`engine/psych/registry.ts`) directement dans `TraitData.capabilities` (`psychType`/`psychImmune`/`psychIndice`) + le `TraitInstance` structuré (`value` = Indice, `arg` = id de `groups.json`), zéro code par trait ; sorts en GameOp (cf. ci-dessous, B4 terminé). Le codegen `scripts/gen-registry.mjs` sert les registres « dépose un fichier → intégré » (`src/**/defs/`, rendu + schémas + terrain + icônes).
- **C. Content app-owned** : `src/data/*.json` = SOURCE canonique éditable (le pipeline `all-data.json → build:data` a été RETIRÉ, il écrasait les données curées). Édition **DANS le Compendium** (toggle DEV « ✏️ Éditer » → `CodexEdit`, champs inférés de la donnée + autocomplétion `<datalist>` sur les références) — PAS un éditeur autonome séparé (`src/ui/dataEditor/` supprimé après retour user : dupliquait le Compendium, moins bien, pas d'aide à la saisie). Fondation : `src/data/overrides.ts` (`setDataset`/`resetData` mutent EN PLACE, jamais de réassignation) + `serializeDataset` (round-trip byte-fidèle, `JSON.stringify(_,null,2)` sans newline finale) + `fsPersist.ts` (File System Access API : connect/restore handle IndexedDB, repli `downloadText`). **Recette = MANUELLE** (le folder-picker FS-Access n'est pas automatisable Playwright).

**Modèle de créature unifié** (espèce→sous-type→nommé ; LDB=sous-types `title=null`+optionals, nommés=`title`, partition par title/optionals PAS par livre) : **le rig se résout sur la DONNÉE, jamais sur le NOM de la créature** — `appearance.species` explicite → `bipedDef()` (`gameIso/rig/composeRig.tsx`), verrouillé par `rig/golden/creature-resolution-golden.test.ts`. Même invariant pour la carrière (portée explicitement par l'entité, `enemyProfile.test.ts`) et pour le tell mutant (lu dans `c.mutations`) : aucune regex sur libellé nulle part dans la chaîne de rendu.

**Sorts (B4) TERMINÉ** : 243/243 sorts curés en `GameOp`. Ops/champs : `gainFortune`/`gainFate` (retrait des non-dépensés à l'expiration), `SpellSpec.lifeSteal` (vol de vie missile), `SpellSpec.casterOps` (effets sur le lanceur), `ZoneEffect.heal`. **Moteur d'invocation** (`state/summonFlow.ts` : `applySummon`/`purgeExpiredSummons`) fait entrer une créature du bestiaire en combat, insérée dans l'initiative, dissipée au franchissement de Round. `enchantWeapon.onHitTest` : Test à la touche gaté par Groupe (`onlyGroups`/`exceptGroups`). Restent en `narrative` (limite RAW acceptée) : enchant +DR Dégâts/ignore-PA, Péché sur fausse accusation, polymorphe à remplacement de carac, scrying.

**Refonte combatFlow — PLAN 7 PHASES COMPLET (7/7)** : god-files (combatFlow ~4065 l., store ~3678 l.) décomposés via le patron DÉJÀ existant `cascadeAppliers` (registre peuplé par effet de bord d'import). Cible `state/combatHooks.ts` (`registerCombatHook`/`runCombatHooks`, cycle de vie battleStart/turnStart/turnEnd/roundBoundary/attackResolved/castResolved/miscast/battleEnd, filtré par `policy.rule`). Livré : boucles de Round → `state/combat/roundHooks.ts` ; `runEnemyAI` → `state/combat/turnHooks.ts` ; `applyAttackResult` → registre `state/combat/hitModifiers.ts` (ward-saves/arrow-ward/dome-ward/martyr/pushback, ordonnés) ; générateur `rollFlowActions`/`rollFlowActionsMulti` (types mappés template-literal, surface prouvée identique par tsc) ; god-switch `applyEffects` → registre `EFFECT_HANDLERS` (`combatEffects.ts`, exhaustivité par type mappé `{[K in Effect['type']]:...}`) ; manifeste `STATE_FIELDS` (`stateFields.ts`, `initialFields()`/`resetFields(scope)`) ; `~2025 l.` de combat inline → `src/state/combatSlice.ts` (`createCombatSlice`, store 3449→1424 l., **surface prouvée identique : 425 clés `useGame.getState()` avant==après**). **3 goldens protègent l'iso-comportement** : `roundBoundary.golden.test`, `turnStart.golden.test`, `hitSaves.golden.test` — à relancer après toute retouche combat.
