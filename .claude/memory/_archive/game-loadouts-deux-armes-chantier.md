Successeur du « sélecteur d'arme » différé (lisibilité combat) : l'utilisateur a élargi en **système de loadouts** (sets d'armes nommés que le joueur construit hors combat et commute en combat) + **combat à deux armes complet**.

**Spec** : `docs/superpowers/specs/2026-06-10-loadouts-deux-armes-design.md` (RAW vérifié, ne pas re-sourcer à l'aveugle). **Plan #1** : `docs/superpowers/plans/2026-06-10-loadouts-p1-fondation-moteur.md` (Phase 0+1, 7 tasks TDD, code réel). Plans #2 (constructeur UI fiche), #3 (combat : choix arme attaque/parade + switch + verrou équipement), #4 (Maniement de deux armes) à écrire ENSUITE contre l'API posée.

**RAW vérifié (décisions figées avec l'utilisateur)** :
- Combat à 2 armes (LDB 14 l.177-183) : 1 arme 1 main/main, **attaque main secondaire = -20** ; frapper des DEUX = talent **Maniement de deux armes** (l.633-638 : d100 **inversé** pour la 2e, conditionnelle à la réussite de la 1ère, cible au choix, nouvelle défense, **-10 défense jusqu'au prochain Tour**, Avantage si les **deux** touchent, exception Critique). **INCLUS** dans le chantier.
- Ambidextre (LDB 10 l.30-32) : -20→-10(1×)→0(2×).
- Parade (LDB 62 l.192) : arme 1 main **Défensive** + spé **Corps à corps (Parade)** → parer **sans le -20** main secondaire. Défensive = +1 DR (déjà dans finishMelee).
- Switch de loadout = **Action gratuite, 1/tour, AUTORISÉ même Engagé** (LDB 13 l.116 « peut interdire » = discrétion ; un archer chargé doit pouvoir dégainer). Le cap 1/tour évite l'abus.
- **En combat, seul le switch change l'équipement** : armure + brassage inventaire = **hors combat** (corrige le permissif actuel ; aucune règle d'enfilage RAW).
- Maniement de deux armes BORNÉ à l'attaque-**Action** : jamais sur une attaque GRATUITE (Frénésie l.34, attaques gratuites de créature, Piétinement, future Riposte). Le **choix d'arme mono** (avec -20), lui, s'applique partout.
- Héros only (ennemis = auto-choix statbloc).

**« Préparer le terrain » (demande explicite)** : registre **`src/engine/combatFeatures/`** calqué sur `qualities/` (registry+normalize+dispatch) — talents+traits deviennent 1 entrée. Hooks : `modifyOffHandPenalty` (Ambidextre, livré), `attackModes` (Maniement, plan #4), `onWonDefense` (Riposte talent l.843-852 « arme Rapide → dégâts comme son Action » ET Champion trait LDB 85 l.55-56 « défense gagnée → dégâts comme attaquant » = MÊME hook), `attackMods`/`defenseMods` (futur). Pas de dispatcher mort (hook câblé à l'arrivée de son 1er consommateur).
