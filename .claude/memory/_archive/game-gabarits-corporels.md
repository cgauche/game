Objectif utilisateur (2026-06-05) : **pouvoir ajouter facilement des monstres de toute taille**, humanoïdes (nain/humain/mutant/skaven…) ET 4-pattes (cheval/loup/sanglier/rat…) ET ailés (griffon/pégase/hippogriffe), « pas les mêmes animations que les 2 jambes ». Un dragon = gabarit ailé à grande échelle (la taille est un paramètre `PROPS`, pas un modèle bespoke).

**Décision d'archi** : généraliser le rig autour de **gabarits corporels**. Un gabarit = squelette (os + proportions) + pose de repos + ses propres anims (démarche…) + facing. La machinerie est DÉJÀ générique et partagée : FK (`kinematics.worldTransformsG`), palette tokenisée (`buildTokenMap`/`applyTokenMap`), facing, pose de mort, recolor. Seule la liste d'os était figée au bipède.

**Pourquoi les monstres « semblaient différents »** : `classifyEnemy`/`CREATURE_RE` (enemyProfile.ts) route skaven/orc/gobelin/homme-bête/mort-vivant vers le **sprite monolithique** (blob SVG sur dégradés partagés `url(#g_mut)`…, non recoloriable), alors que ce sont des bipèdes → ils devraient passer par le rig. Le monolithique = legacy qui rétrécit phase par phase ; ne reste que pour les vraies bêtes exotiques (araignée 8 pattes, serpent, dragon) en attendant.

**Phasage validé** : P1 bipèdes (skaven, peaux-vertes, hommes-bêtes, morts-vivants, vampire, troll, ogre, démons humanoïdes — réutilise le rig à 95 %), P2 quadrupèdes (nouveau squelette + démarche), P3 ailés (quadruped + ailes). Exotiques = P4/jamais. **L'utilisateur a demandé de PROUVER le quadrupède EN PREMIER** (de-risque le nouveau squelette+gait avant d'industrialiser les bipèdes).
