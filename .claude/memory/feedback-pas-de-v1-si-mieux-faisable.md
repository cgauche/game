**Verbatim (2026-07-11, arbitrage maquette hub #343)** : « J'aime pas les v1 quand on peut faire v2 ou v3 directement. Mais j'avoue que pour le moment ... lister les services à gauche ça me va. »

**Why :** l'étagement v1→v2 crée du travail jeté et du legacy ; le user préfère viser directement la bonne version. Il TOLÈRE un périmètre réduit pragmatique (le hub-liste avant le plan de quartiers) quand la marche est réelle — mais le périmètre retenu doit être construit à sa forme FINALE, pas en brouillon à refaire.

**How to apply :** avant de proposer une « v1 », se demander si la v2/v3 est réellement hors de portée — si non, viser directement. Si un étagement s'impose (dépendance de données, arbitrage en attente), le dire explicitement ET concevoir la v1 pour que la v2 s'y AJOUTE sans rien réécrire (ex. #343 : hub-liste bâti sur les mêmes données/primitives que le futur plan de quartiers — MapCanvas partagée).
