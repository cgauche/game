Les symptômes de maladie (LDB 20) sont une **entité de donnée** éditable au Codex (`src/data/symptoms.json`), plus un enum. Mécaniques en **3 canaux** comme un trait/qualité (cf. [[game-talents-editable-data]]) :
- `passive` / `passiveBySeverity` (charMod, op `condition`…) : pénalités continues (fièvre/bubons −10 ; convulsions −10 base, −20 aux paliers `moderee`/`grave` portés par l'instance) ET États PORTÉS (Fièvre (Grave) → Inconscient LDB 20 l.170, Malaise → Exténué l.188), matérialisés par `syncDerivedConditions` (marquage `ConditionInstance.derivedFrom`) → collectées par `diseasePassiveOps(c)` → `passiveMods` (kind 'maladie'). Ces passifs ne sont annulés par AUCUN annulateur (`PASSIVE_CANCELLERS.maladie` est vide : LDB 17 l.59-61 n'ouvre la Détermination que sur Psychologie / Critique / retrait d'UN État) ; ce qui les lève est la SUSPENSION de la SOURCE (`engine/suspension.ts` — `suspendSource`/`sourceSuspended` sur `ActiveEffect.suppressedSource`, identité Codex ; `suspendSymptom`/`symptomSuppressed` n'en sont plus que la spécialisation d'une ligne), à durée, filtrée au collecteur unique `passiveMods`. Limite mesurée : les émetteurs SANS `src` (séquelles, Faim, Soif, Ivresse) sont insuspendables par ce canal.
- `onTick { difficulty, onFail: GameOp[] }` : Test de cycle quotidien (Blessé → `contractDisease` 'blessure-purulente' ; Toxine) — DIFFÉRÉ en cascade de nuit influençable ; la conséquence `onFail` est appliquée par `applyOps` côté `restFlow` (applier `diseaseTick`). `disease.ts` reste **pur** (importe `ops` en TYPE seul → zéro cycle ops↔disease ; seule liaison croisée depuis #1599 : `conditions.ts`, pour poser les États par `addCondition`).
- `capabilities` irréductibles lues par la machinerie de cycle : `blocksHealing`, `amputation`, `contagious`, `nausea`, `endTest`, `persistentActive`. **Ce qu'un Point de Détermination fait sur l'État qu'un passif porte n'est PLUS un drapeau de symptôme** (#1599, 2026-09-06) : `determinationSuspends`/`lockedUntilCured` sont MORTS, l'op `condition` porte sa `resolveWindow` (`engine/ops.ts`) — `'none'` = refus (Malaise, LDB 20 l.188), `{scale:'clock', minutes:{rule:'maladie-conscience-determination-minutes'}}` (Fièvre Grave, l.170), absente = défaut d'UN Round (LDB 16 l.117). Lue par `fenetreDetermination`/`raisonRefusDetermination` (`engine/conditions.ts`), qui retrouvent l'op ÉMETTRICE par `derivedFrom.src` dans `passiveMods` — aucun lookup de catalogue, donc N'IMPORTE quel porteur (mutation, trait, État, objet) porte son État au même socle.
- **ATTÉNUATION À DURÉE** (`attenuateDiseaseSymptom`/`severiteEffective`/`attenuationEchelons`, LDB 20 l.159 « permettent d'atténuer les symptômes pendant une journée, transformant Grave en Modéré et Modéré en convulsions normales ») : l'instance n'est JAMAIS mutée — un `ActiveEffect.attenuatedSymptom` porte l'échelon et l'horloge le rend. **UNE dose active à la fois** par (maladie, symptôme) : une 2ᵉ REMPLACE la première. `severiteEffective` est la source unique lue par `symptomPassive` ET par le cycle quotidien (`symptomOnTick`, paramètre `severite`) — une demi-migration (passifs atténués, cycle resté au palier porté) a existé et est refermée.
- **NON-CUMUL** : ce n'est pas une affaire de symptôme mais un drapeau de l'ÉTAT (`nonCumulable` dans `src/data/etats.json` — `a-terre`, `inconscient`, `surpris` ; LDB 16 l.115/l.37/l.137), appliqué par `empileSurPionExistant`. Corollaire : tout poseur d'État du cycle de maladie passe par `addCondition` (source unique) — le cycle quotidien poussait ses pions à la main, il ne le fait plus.

`maladie.symptoms[]` = `{ symptomId, severity?, difficulty? }` (référence le catalogue). Op GameOp **`contractDisease`** ajouté (contraction immédiate, complète `exposeDisease`). Catégorie Codex « Symptômes » + éditeurs (`SymptomTickField`). Commit c4a0ab7d.

**Why :** demande user « Symptoms devrait aussi utiliser les GameOps de toute évidence » + tout doit être éditable au Codex en donnée, pas en code. Option « triggers génériques » écartée (réutilisation insuffisante — cf. cascade quotidienne = machinerie + `ScheduledEffect` existe déjà).

**How to apply :** ajouter un symptôme = UNE entrée `symptoms.json` (ou via Codex « Symptômes ») ; sa conséquence de test = GameOp dans `onTick.onFail`, jamais du code ; un comportement vraiment irréductible = un drapeau `capabilities` lu par `disease.ts`. Exemple worked (commit 83fb4d90) : « Crampes abdominales » (Colique, T2C) = `passive` charMod −20 à tous les Tests, référencé en symptôme primaire de la Colique ; sa cascade d'échec par-Test (Sonné/À Terre/Inconscient) n'a pas de trigger → laissée en `desc`.
