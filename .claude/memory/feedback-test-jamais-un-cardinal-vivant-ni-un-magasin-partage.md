Vécu 2026-09-05 (L3 #1679, gates rouges après rebase) : deux tests écrits SUR MON BRIEF (« le test porte TA mesure ») assertaient l'état vivant — les cardinaux des stocks réels (`slotsStock` 339, `structuresStock` 1049) et le nombre de fichiers d'une COPIE du magasin des justificatifs. Entre l'écriture et les gates, une autre session avait fait DÉCROÎTRE deux stocks (le comportement souhaité d'un stock), et les gates concurrentes écrivaient dans le magasin pendant la copie (1024 ≠ 1026). Le juge de design l'avait dit dès la première passe : « faire porter au test l'assertion de PORTÉE, jamais un cardinal brut de 73 ».

Vécu 2026-09-06 (main ROUGE sur 1658c946a, #1686 lot 3a-2 — a bloqué le push C3 de #1389) : troisième forme de la même classe, le test qui MUTE EN PLACE un module-global partagé (`grammaire.test.ts:1038` réécrit `IDS_PAR_DATASET['etats.json']` puis restaure). Le jour où `ref.ts` a gagné un second régime (`idsVivants(dataset) ?? IDS_PAR_DATASET[dataset]`), la source vivante posée par `overrides.ts` — chargé ou non par un test PRÉCÉDENT du même worker — a shadowé la mutation : vert en local (6 cœurs), rouge en CI, rouge NON attribuable à première vue. Un test qui a besoin d'un régime le POSE lui-même sur une fixture (`poserSourceDIdsVivants({ entrees, discriminantDe })` + restauration), il ne mute jamais le registre partagé. Corollaire pour les juges de diff : quand un module gagne une source de vérité ALTERNATIVE, chercher les tests qui mutaient l'ancienne.

Vécu 2026-09-07 (#1709 lot D0) : quatrième forme, le test-PHOTOGRAPHIE d'une carte éditable — `diligence-projet.test.ts` figeait 668 murs, 422 surfaces, 18 pièces, 44 murs périphériques, le cellier à 12/12/8, 32×38, les paliers `[1,2,3,4]`, les ids des scènes ; `arene-projet.test.ts` les 18 scènes du projet. User (verbatim) : « diligence-projet.test.ts, c'est le truc qui fait que si je veux modifier cette carte vue qu'elle est dans mes scénarios, le test devient rouge et qu'on doit le modifier a chaque fois ? » — oui, et c'est contraire à [[feedback-toute-donnee-de-scene-editable-sans-ia]]. Le CONTRAT était pourtant écrit en tête du fichier (« la scène se charge, et l'étage se rejoint à pied ») : les propriétés (aucune porte orpheline, étage desservi, cellier atteint, `pathTo` réel) restent, les comptes tombent ; la preuve exigée est double — une mutation qui casse le contrat rougit, un AJOUT LÉGITIME sur la carte laisse vert.

**Why:** un cardinal vivant change par le travail NORMAL des autres sessions — ou de l'utilisateur qui édite sa carte ; un magasin partagé (`<git-common-dir>/…`) est écrit en continu par leurs gates. Un tel test rougit sans défaut, et son rouge s'attribue au mauvais commit — exactement la classe « rouge non attribuable » que la porte de stock existe pour rendre visible ([[feedback-attribution-rouge-suite-sonde-arbre-committe]]).

**How to apply:** le test asserte une RÈGLE sur une fixture nommée (les formes, les cas limites) et, sur le corpus réel, seulement un INVARIANT stable (`> 0`, « la voie précise ne voit pas moins que le repli », clés complètes avant = après sur un magasin SYNTHÉTIQUE) ; un chiffre vivant s'imprime dans le message de diagnostic, jamais dans l'assertion. Une fenêtre de commits à SHAS FIGÉS est une fixture (déterministe), un stock réel à HEAD ne l'est pas. Une contre-épreuve sur le magasin réel est une SONDE jouée au rendu, pas un test de gate. Voir [[feedback-gardes-structurelles-pas-greps]], [[feedback-mes-propres-sondes-se-remesurent]].
