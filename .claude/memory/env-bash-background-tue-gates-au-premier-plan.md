**Faits (2026-09-02, session L3 #1659)** : `npm test` (suite complète ~9 min) + `tsc` + `eslint` chaînés en Bash `run_in_background` → notification « killed » deux fois de suite (suite interrompue à mi-course, le fichier d'exit jamais écrit), alors que la même chaîne avait abouti une fois plus tôt. Relancée AU PREMIER PLAN (`timeout: 600000`), suite seule puis tsc/eslint/docs dans un second appel : verte.

Le dossier de job (`~/.claude/jobs/<id>/tmp`) vaut le job COURANT : un script écrit sous l'ancien id n'existe pas sous le nouveau, et le hook pre-commit du dépôt refuse un message de commit dont le chemin de fichier passe par une variable d'environnement (« message en fichier illisible pour le contrôle de solde ») — il faut le chemin LITTÉRAL. Le même hook pattern-matche ce texte jusque dans un heredoc : écrire les fiches mémoire avec l'outil Write.

**How to apply :** gates lourds au premier plan, en deux appels (suite seule ≤ 10 min, puis tsc+eslint+docs) ; chemins littéraux dans tout fichier de message ou de corps ; vérifier l'existence d'un script de job avant de l'appeler.

**Complément 2026-09-02 (hook de solde `scripts/hooks/solde-ticket-guard.mjs`)** : pour un commit `corrige #N` depuis un worktree, le hook (a) lit le solde sur le DISQUE à la racine du dépôt PRINCIPAL (emplacement du script) ET dans l'INDEX du répertoire ciblé par le premier `cd <chemin>` de la commande — un `cd $VAR` non expansé le fait échouer (« non stagé ») : écrire le `cd` en chemin LITTÉRAL ; (b) tourne AVANT la commande : le `git add` du solde doit être une commande SÉPARÉE, antérieure ; (c) exige une copie du solde à la racine principale (untracked, à retirer après le `pull --ff-only`) ; (d) chaque item de `## Restes` finit par `-> #N` seul, `-> corrigé dans ce commit`, ou `-> RAS : …`.

**Complément 2026-09-05 (L2bis)** : le garde-mémoire du harnais tue une commande Bash de FOND « because the system is running low on memory » avec tout son arbre de processus — deux fois de suite sur `node scripts/gates/toutes.mjs` alors que 8-13 Go de RAM étaient libres (la pression venait des autres sessions : banc de 37 agents, codeurs voisins) ; le runner meurt au milieu des lanes, aucun résumé, un veilleur qui attend le résumé expire. Contournement mesuré : `spawn(process.execPath, [script], { detached: true, stdio: fichiers, windowsHide: true })` + `unref()` depuis un script node (`lancer-detache.mjs` du scratchpad) — le groupe détaché survit au harnais — puis un veilleur léger (`attendre-gates-puis-push.mjs`, un `stat` toutes les 15 s) qui pousse au résumé vert. PowerShell `Start-Process` est bloqué par l allowlist lean-ctx dès qu il y a une variable.
